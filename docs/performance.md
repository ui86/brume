# 实现说明与性能基准

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `src/config.rs` | 解析命令行参数，校验认证配置及 IP/CIDR 白名单 |
| `src/dns.rs` | 使用配置的 DNS 服务器解析目标域名并缓存结果 |
| `src/protocol.rs` | 解析和编码 SOCKS5 请求、回复及 UDP 数据报 |
| `src/server.rs` | 监听 TCP/UDP、处理认证、转发流量并维护 UDP 关联 |
| `src/client.rs` | 提供 TCP CONNECT 和 UDP ASSOCIATE 客户端接口 |
| `src/main.rs`、`src/lib.rs` | 启动服务及导出公共库模块 |

服务端在同一端口监听 IPv4 和 IPv6 的 TCP、UDP 流量。Tokio 运行时为每个 TCP 客户端创建异步任务，建立 CONNECT 后进行双向转发并支持半关闭。TCP 客户端最多同时处理 2048 个。启用 `tcp_timeout` 时，任一方向成功转发数据都会刷新整个连接的空闲期限，写入阻塞也受该期限约束。

UDP 接收循环最多允许 256 个并发数据包处理任务，所有关联合计最多保留 1024 个目标流，每个关联最多 128 个目标流；达到上限时，新连接或数据报会被拒绝或丢弃。同一目标的并发首包共用一次建流过程。每个目标流有独立的异步回复任务和约 64 KiB 接收缓冲区；请求和回复都会刷新流的空闲期限，TCP 控制连接关闭后会立即取消回复任务。TCP 和 UDP 域名目标通过配置的 DNS 服务器解析，解析器复用服务端运行时，并按记录 TTL 缓存最多 8192 条响应；IP 目标直接使用地址。

UDP 数据报必须属于存活的 TCP 关联，来源 IP 与控制连接一致。客户端库会在关联请求中声明实际 UDP 端口；服务端按来源端点索引关联。外部客户端请求端口为 `0` 时，首个有效数据报确定来源端口；同一 IP 只能同时保留一个尚未绑定的端口 `0` 关联。UDP 域名目标在建流或发送失败时尝试其他解析地址；未收到回复的流到期后，下个数据报会从后续地址开始。白名单同时检查 TCP 和 UDP 来源地址，未配置时允许所有来源。白名单地址和网段采用顺序查找。

## 验证

```bash
cargo fmt --all -- --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-targets
```

测试覆盖 IPv4、IPv6 和域名报文、UDP 数据报校验、白名单、命令行参数、认证、TCP 半关闭与单向传输、UDP 关联和流到期、自定义 DNS 与缓存，以及客户端库的端到端连接。GitHub Actions 的 CI 执行上述检查及安装脚本测试；发布工作流构建并用 UPX 压缩 Linux amd64 和 arm64 的静态链接程序。

## 运行基准

```bash
cargo bench --features performance-bench --bench benchmarks --locked
```

以下数据于 2026-10-09 在 Windows、Intel Core i5-12600KF、4 个可用逻辑处理器、Rust 1.98.1 环境测得。基准程序每项先预热，再运行 5 轮，表格列出每次操作耗时的中位数。TCP 和 UDP 代理场景使用本机接收端或回显端，结果包含本机网络栈、线程调度和客户端处理开销。

| 场景 | 本机测量值 |
| --- | ---: |
| UDP IPv4 数据报解析，1024 字节 | 7.00 ns/包 |
| UDP 域名数据报解析，1024 字节 | 46.54 ns/包 |
| UDP IPv4 数据报编码，1024 字节 | 50.53 ns/包 |
| 小白名单命中／未命中 | 7.05／7.30 ns/次 |
| 256 个网段白名单未命中 | 247.44 ns/次 |
| UDP 顺序代理往返，1024 字节 | 102.06 μs/包 |
| UDP 16 包流水线收发，1024 字节 | 18.30 μs/包 |
| TCP 连接目标并完成 SOCKS5 协商 | 5.19 ms/连接 |
| TCP 代理往返，1 KiB | 61.23 μs/次 |
| TCP 代理上传并等待确认，1 MiB | 0.82 ms/次 |

这些数字是本机环境的参考值，不能代表公网延迟或 Linux 部署性能。TCP 新建连接样本每轮 200 次，前一次运行的中位数为 6.80 ms；数值仍会受本机调度影响，不宜用它比较微小的连接优化。当前实现使用异步任务，并对 TCP 客户端、UDP 数据包任务和目标流设有上限；UDP 关联按来源端点索引，白名单仍顺序查找。并发连接数、目标数和数据包速率变化时，耗时可能不同。评估实际部署性能时，应在目标机器上按预期负载重新运行基准。
